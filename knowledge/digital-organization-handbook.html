Executive Summary

A digital organization is not a remote-work company. It is an enterprise that operates under one identity, one product registry, and every AI agent registered and tested. This handbook codifies the daily operating methodology.

The Operating Loop

Every morning, four rituals:

  • Audit — python3 ~/.hermes/brainsait/scripts/audit.py. If it exits non-zero, nothing else matters.
  • Briefing — cronjob daily-briefing.sh runs the prior-day activity, surfaces anomalies, prepares the day.
  • Registry reconcile — verify the Intelligence Graph against the live stack.
  • Directive check — confirm no work in flight violates any BSD-2026-07 article.

Identity Architecture

Every person, system, and agent in the enterprise carries an identity under OID 1.3.6.1.4.1.61026. The Identity layer is the authentication substrate; every other layer assumes it.

Person identity: SSO via the profile service (port 9600), backed by enterprise identity records.

System identity: API keys registered under the same OID hierarchy. Every key is auditable.

Agent identity: registered under domain arc (e.g. .8.1 for MASTERLINC). Every agent has a name, a mandate, and an AI Metadata record.

Product Lifecycle

Five stages:

  • Conceive — Article 12 fields defined; OID arc allocated.
  • Build — implementation; AI Metadata populated as it lands.
  • Register — registry node created; catalog entry linked.
  • Ship — marketplace listing live; JSON-LD published.
  • Iterate — versioned changelog; weekly validation re-run.

A product that skips a stage is, by directive, pre-release. Marketing it as shipped is non-compliant.

Agent Governance

Every AI agent has:

  • A registered name in the LINC family.
  • An OID arc allocation.
  • A mandate (what it is allowed to do).
  • A model card (which model, which version, which validation set).
  • An override path (how a human operator can take over).
  • A changelog (validation runs, drift events, manual overrides).

Agents without these six attributes are unauthorized and must not be deployed.

Documentation Discipline

Every project maintains nine documents (Directive Article 14):

  • Executive Summary
  • Technical Documentation
  • API Documentation
  • Deployment Guide
  • Architecture Diagram
  • User Guide
  • Administrator Guide
  • AI Agent Specification
  • Release Notes

A project missing any of these is not shippable. The auditor enforces this.

Marketplace Discipline

The marketplace is the distribution surface. Direct, unlisted distribution is deprecated.

Every listing carries:

  • Bilingual name + description.
  • SAR + USD pricing.
  • schema.org JSON-LD with OID brand identifier.
  • Cross-link to registry node.

Listings without these attributes are pre-listings.

Compliance Routine

Daily:

  • Check for new NPHIES rule changes; update ClaimLinc validation set if needed.
  • Verify PDPL consent ledger integrity.

Weekly:

  • Re-run all agent validation sets.
  • Re-validate every product against its compliance block.

Monthly:

  • External conformance suite against CHI NPHIES tests.
  • Internal conformance against FHIR R4.

The Audit Principle

The auditor is the operational definition of "the directive is being honored." If the auditor passes, the directive is being honored. If the auditor fails, the directive is being violated, regardless of intent.

Two rules:

  • Never ship with a failing auditor. The auditor's exit code is binding.
  • Always extend the auditor when you amend the directive. Enforcement cannot drift silently.

Daily Checklist

  • [ ] Audit exited 0
  • [ ] Briefing reviewed, anomalies flagged
  • [ ] Registry reconciled
  • [ ] No directive violations in flight
  • [ ] Identity layer healthy (SSO responds)
  • [ ] All services respond on their assigned ports (per port map)
  • [ ] Backups taken; last backup <24h old

Weekly Checklist

  • [ ] All agent validation sets re-run
  • [ ] Every product compliance block re-validated
  • [ ] Registry intelligence graph regenerated
  • [ ] Marketplace JSON-LD regenerated
  • [ ] Backup restore test performed

Monthly Checklist

  • [ ] External conformance suite (NPHIES)
  • [ ] FHIR R4 internal conformance
  • [ ] OID hierarchy audit (no orphaned nodes, no renumbered arcs)
  • [ ] Cross-domain navigation verified
  • [ ] Directive amendment review (BSD-YYYY-NN v1.x)

Closing Principle

A digital organization is not measured by its size or revenue. It is measured by whether the directive is being honored and the auditor is passing.

Everything else is decoration.
